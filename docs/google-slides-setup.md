# Google Slidesに初期版を設置する

この版は資料に紐づくApps Scriptとサイドバーです。Marketplace公開済みのEditorアドオンではありません。Workspace Studioは使いません。会社でApps Scriptが許可されていても、実行権限・外部パッケージ・原本の共有方法は実環境で確認してください。

## 担当者による一度の設置

1. `npm ci` でビルドした後、READMEのデモまたは非公開パックを作成します。
2. `build-google --pack <非公開パック> --out <新しい出力フォルダ> --draft` でテスト用の7ファイルを作ります。承認済みの本番用には `--draft` を付けません。
3. パック内の `source/template.pptx` をDriveへアップロードし、Google Slides形式で開いて保存します。元PPTXのOffice編集モードで実行しないでください。非公開のコピーで作業します。
4. Slidesの「拡張機能 → Apps Script」を開きます。生成した `Core.gs`、`Addon.gs`、`Recovery.gs`、`Diagnostics.gs`、`Catalog.gs`、`Sidebar.html` を同名のファイルへコピーします。`Sidebar` はHTMLファイルとして作成します。初期の空の `Code.gs` は削除して構いません。以前の設置を更新する場合も、コードを生成し直し、`Recovery.gs` と `Diagnostics.gs` を含めて反映してください。
5. Apps Scriptのプロジェクト設定でマニフェスト表示を有効にし、生成した `appsscript.json` の内容を反映します。`presentations.currentonly` と `script.container.ui` を指定し、Drive全体へのアクセスやモデルAPIキーは使いません。
6. 保存し、エディタから `inspectCurrentPresentation` を実行して読み取りの成否を確認できます。会社のアカウントで要求された権限を確認し、許可します。表示・タグ・固定部分・ノートを確認したコピーで `registerCurrentTemplate` を実行します。診断合格を描画確認の代わりには使いません。
7. Slidesを再読み込みすると「AI資料作成」メニューが出ます。「作成・修正」からサイドバーを開きます。

この初期版にWebアプリのURLや「デプロイ → 新しいデプロイ」は不要です。生成される `Catalog.gs` は会社固有の情報です。公開GitHubへの追加や他社への配布はしないでください。スクリプトのコードを編集できる人はその設定も変更できるため、承認状態をアクセス制御の代わりに使えません。

## 一般利用者の操作

1. 担当者が管理する原本を作業用にコピーします。最初に、コピー先でも紐づくスクリプト・メニュー・認証が利用できることを確認してください。
2. 目的、相手、今回の情報を入力します。情報の名前を1行に1つ登録し、本文にも同じ名前を付けます。例えば「商談メモ」「商品説明」です。
3. 「AIへの指示をコピー」を押し、会社で使用できるGemini Web等へ貼り付けます。回答をサイドバーへそのまま貼り、「内容を確認」を押します。
4. 差分と要確認事項を読み、「確認した内容を反映」を押します。原本ページを複製し、指定欄だけに文章を入れ、作業コピー内の元テンプレートページを取り除きます。
5. 数字・条件・根拠・文字の収まりを実物で確認します。必要ならSlidesで手修正します。
6. 同じ構成を更新する場合は、新しい回答を確認します。手修正と競合する欄は既定で保持し、その欄だけ明示的に上書きを選べます。保持した文章は根拠の再確認が必要な状態として扱います。

AIの回答が容量等に違反する場合は、表示された問題と同じ仕様をAIへ返し、回答を修正させます。文字数の範囲内でも、折り返し・禁則処理・フォントの置き換えによって溢れることがあります。自動でフォントを縮小して解決しません。

## 試験・承認・復元

会社資料を使う前に、`npm run smoke -- work/google-smoke` で架空の試験一式を作成できます。原本PPTX、設置コード、9つの回答JSON、順序付きの `RUNBOOK.md` を出力します。正常・短文・仕様上限の日本語・改行・繰り返し・更新はローカル検査に合格し、容量超過・未知の根拠ID・空の必須欄は拒否されることを確認して生成します。実際のGoogleでの実行やテンプレート承認は行いません。

最短文、通常文、最大容量の日本語、明示改行、繰り返すページ、表セル、グループ、手修正保持、上書き、同じ実行の再試行を試します。原本から作業コピーを作り直す復元試験も行います。元PPTXとSlidesと書き出したPDFを比較し、会社のデザイン担当者が許容するか判断します。

確認した基準PDF/PNG/JPGを非公開に保存し、ローカルの `approve` を担当者が実行します。その後、本番用コードを新しいフォルダへ生成し、管理する原本のスクリプトへ反映します。初期版は管理者による手動配布です。組織向けの一括更新・Marketplace配布・カタログ同期は今後の開発対象です。

## 失敗した場合

通常の例外では、新規作成中の一時ページを除去し、更新中の文章と記録の復元を試みます。最後の原本整理中に失敗した場合は、生成済みページを残し、同じ回答・同じ実行IDで再試行します。

実行ID、反映予定の回答、根拠IDの一覧、手修正の保持・上書きの選択を、この紐づくスクリプトの `UserProperties` へ保存してから変更を始めます。通常の利用では、同じ利用者が同じ資料・同じ版でサイドバーを開き直すと復元します。復元時の自動実行はなく、資料を確認して「前回の反映を再試行」を押します。異なる内容や別の実行IDへ差し替えることはできません。

保存は1利用者・1資料に1件です。ASCIIに変換した保存内容を7,000文字ずつに分け、全体200,000文字までに制限します。日本語・絵文字は変換後に長くなるため、回答の文字数とこの上限は同じではありません。容量超過・保存失敗・整合性の不一致では変更前に停止します。入力メモ全体やAIとの会話履歴は保存しません。反映した資料を明示的に保存した後、記録を削除します。記録の整理だけに失敗した場合は成功結果にその旨を表示します。

内容を変えたい場合は「前回の記録を解除して確認し直す」を使います。この操作は資料を復元せず、再試行の記録だけを削除します。資料が途中状態・混在状態の場合は解除を拒否します。保留記録は成功または明示的な解除まで残るため、放置せず担当者が確認してください。

Apps Scriptの強制タイムアウト、ネットワーク断、復元処理自体の失敗は完全なトランザクションになりません。保留実行の内容を再取得できても、作成・更新の途中状態をすべて自動復元できるわけではありません。途中で人が内容を変えた場合や状態が破損した場合は推測で続行せず停止します。作業コピーを保管し、担当者が状態を確認するか、原本からコピーを作り直してください。

DocumentLockはスクリプト同士の競合を防ぎますが、人がSlidesを同時編集する操作まではロックしません。反映中は同時編集を避け、終了後に結果を確認してください。

## 設定・状態の診断

メニューの「設定・状態を確認」は読取専用です。未登録原本のタグ、登録した欄、取得可能な固定部分、原本のページ数と順序、反映の段階、手修正判定の基準、現在の利用者の保留記録を確認します。資料・ノート・Propertiesは書き換えず、承認・解除・復旧も実行しません。

結果はその資料の画面内に表示し、自動送信しません。本文・ノート本文・可変欄の値・資料ID・利用者ID・画像URLは報告に含めません。失敗した確認項目とページ番号を、担当者が設置や対応範囲の切り分けに使えます。成功しても手修正の内容、根拠、文字の収まり、全マスターや画像内容を保証しません。未登録の配布コピーと破損資料の判別にも限界があります。

## ノートと外部共有

更新用の機械記録を各ページのスピーカーノートに保存します。通常の発表者ノートは保持しますが、元の顧客情報が残っていないか確認が必要です。記録を削除・改変した資料は更新を停止します。

外部共有の前に、完了した作業資料からSlidesの「コピーを作成」で別コピーを作り、そのコピーで「AI資料作成 → 配布コピーのノートを削除」を実行できます。削除の確認後、更新用記録と通常の発表者ノートをすべて消去します。本文と元の作業資料は変更しません。コピー先にスクリプト・メニューが引き継がれることは実Googleで確認が必要です。

各ページに記録した作業資料IDが現在の資料IDと同じなら、元資料と判断して削除を拒否します。未完了資料・テンプレート原本・ID記録のない以前の版の生成資料でも停止します。以前の版は先に作業コピー側を新しいコードで更新してから、配布用にコピーしてください。通常の削除エラーではノート本文の復元を試みますが、強制終了・復元の失敗では配布コピーを作り直してください。この保護は誤操作を減らすための記録であり、改ざん防止の署名ではありません。

ノート削除後の配布コピーは更新に使えません。また、本文の顧客情報、コメント、埋め込みデータ、共有権限、紐づくApps Scriptと会社固有の設定は除去しません。この機能だけで外部共有可能とは判断せず、組織の提出方法に従い、PDF等を利用する場合も実際の書き出し内容を確認します。

## 実装上の制限

固定部分の比較は、配置、種類、一部の背景・塗り・線、固定文字、文字書式、取得可能な画像元URLを扱います。画像のピクセル内容、全てのマスター・テーマ・段落設定・リッチテキスト書式を完全に検証するものではありません。元URLが無い画像の差し替え等は検知できない場合があります。

PPTX→Slides変換の互換性は別途確認します。動的グラフ、結合セルの可変欄、要素の自由配置、既存の生成資料のページ追加・削除・並べ替えは対象外です。構成を変える場合は新しい作業コピーを使います。
