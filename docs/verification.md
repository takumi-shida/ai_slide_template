## 実行した検証

環境はLinux、Node.js 24.19.0、npm 11.9.0です。`npm run check` が型検査・ビルド・37件の自動テストを完了しました。

| 対象 | 件数 | 確認した動作 |
| --- | ---: | --- |
| 共通契約 | 9 | JSON取り込み、指定外の操作の拒否、版一致、容量、根拠ID、重複、手修正判定、指示に固定原本を含めない |
| ローカルパック・CLI | 8 | 実PPTXの構造抽出、原本保存、表セル、実ページ順、曖昧なタグ拒否、危険なZIP/XML拒否、承認・基準ファイルの整合性、エラー応答 |
| Slides変更処理 | 17 | Node無しバンドル、複製・欄対応、固定文字保持、手修正、確認後変更、二重実行、通常例外の復元、整理中断の再試行、表・グループ、競合ロック |
| サイドバーと変更処理の連携 | 3 | 実際のサイドバーJSによる既定の手修正保持、選択した上書き、同一実行の再試行 |

Slides API、DOM、Googleの認証はモックです。サイドバーJSとサーバー処理の連携を試験しましたが、実ブラウザの描画・アクセシビリティ・コピー権限・Google APIの互換性は未検証です。承認のテストで使う最小PDFはファイル形式の入口検査用で、表示の証拠ではありません。

架空3ページのデモで、PPTX作成→取り込み→用途・容量調整→計画生成→根拠ID付き検証→Google用コード生成を完了しました。デモは未承認状態のままです。

2つのSkillはSkill Creatorの構造検査を通しました。さらに、実装の会話を共有しない新しいエージェントが `create-slides` を読み、デモパックの検査・指示の取得・計画作成・根拠ID付き検証を完了しました。根拠のない短縮率を作らず、未決事項を残しました。これはSkillの利用手順の試験であり、プラグインホストへの実インストールや資料描画の試験ではありません。

GitHub ActionsにはNode 22/24での同じ検査を設定しています。ここで記載したローカル合格と、GitHub側のCI結果は別です。

## 現時点の判定

初期試行のための実装としては、要件を追跡しながら検証を進められる状態です。本番導入の判定はまだできません。次の必須の検証は、架空パックを実Googleで動かすことと、プラグインの実インストールです。その後、許可された会社資料でデザインと総作業時間を評価します。

初期版で対象外にした部品合成・グラフ更新・構成変更・MCP等を必要な用途では、この版だけで要求を満たしたと判断しません。
