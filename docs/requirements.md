# 要件と実装の対応

## 設計判断

既存資料の見た目を毎回AIに再生成させるより、担当者が定義した可変欄を更新する方式から始めます。初期版では、原本をローカルで管理し、Googleへ変換した承認済み原本を日常利用の基点にします。AIホストから独立した仕様とCLIを共有し、ホストごとの差は配布方法と実行環境に閉じ込めます。

ローカル管理は、インターネットを使わず全ての描画まで完結するという意味ではありません。また、プラグインのマニフェストが読めることと、各ホストで同じ編集機能が動くことを区別します。

## 追加した実装条件

- ページID・原本の順序・欄のタグを明示し、同じタグの複数対象を推測で選ばない。
- AIの出力は閉じたJSON仕様。指定外の欄、版違い、容量超過、未知の根拠IDは反映前に拒否する。
- 手修正を差分で検出し、サイドバーは保持を既定にする。確認後に資料が変われば再確認する。
- 同じ実行IDの再試行はページを二重生成しない。利用者別に反映内容を保存し、開き直しても同じ内容を再試行できる。通常の例外で復元を試み、整理中の中断は生成結果を保持する。
- 配布コピーのノート除去は、元の作業資料や未完了資料では拒否する。通常の発表者ノートも消すことを確認し、本文・権限・スクリプトの扱いは別途確認する。
- 会社資料を公開コードに混ぜず、生成した設定にも秘密情報を入れない前提のデモにする。
- 承認は担当者の表示・復元確認の記録とし、文字数検査を描画検証の代わりに扱わない。

## 次の実装順序

1. 架空3ページを実Googleへ設置し、API・書式保持・表・コピー・再試行を確認する。ここが失敗すれば、適合する書式の範囲を狭めるか、APIの変更方式を修正する。
2. 許可された会社資料の小さな用途で、テンプレートを人が整備し、デザイン担当者と利用者が合格条件を決める。
3. Copilot CLIのAIによる実行、Codex/ChatGPTの導入、Claude Codeの導入完了を検証する。確認バージョンと最小対応バージョンを混同しない。
4. 過去資料の通常流用と比較して、総作業時間と品質が改善するか判断する。
5. 利用が続けば、管理配布、強制中断の復旧範囲、配布ファイルの扱い、ページ構成変更、必要な図解・グラフの順に拡張する。実行内容の永続化と配布コピーのノート除去は実装済みだが、実Googleで確認する。MCPや直接編集の経路は、この判断後に追加する。

最初から全機能を同時に広げるより、原本の価値と利用者の修正時間を守れることを先に検証します。構成変更やグラフが必須の用途では、この初期版はまだ十分ではありません。

## 効果を測る

比較対象は白紙からの作成ではなく、実際の「過去資料を流用して手直しする」作業です。同じ担当者・同程度の課題で順序を入れ替え、慣れの影響を減らします。入力、コピー、AIの待ち時間、確認、修正、書き出し、テンプレート整備・保守を含めて記録します。

| 指標 | 記録するもの |
| --- | --- |
| 総作業時間 | 開始から提出可能まで。整備費は想定利用件数で配賦 |
| 修正負担 | AI回答の再試行、内容修正、表示修正、手修正を戻した回数 |
| 品質 | ブランド逸脱、情報誤り、文字溢れ、会議の目的への適合 |
| 採用 | 担当者が次回も選ぶか、対象外の資料へ無理に使っていないか |

合格基準・比較件数・測定期間は組織で先に決めます。現時点では実績や短縮率を作りません。
