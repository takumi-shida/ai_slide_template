# 営業がブラウザで使うための仕様改訂

更新日: 2026-10-06。これは次の開発の仕様です。現在のコードで実装済みの機能と、追加する機能を分けています。Googleへの設置、追加権限の付与、サービス公開はこの仕様更新では行いません。

## 判断と優先順位

営業が日常操作を承認済みのブラウザ環境だけで完結できることを主要件にします。Node、CLI、Git、デスクトップアプリ、ブラウザ拡張、ローカル常駐プロセスの導入を営業へ要求しません。担当者のPCが停止していても作成・修正できることが必要です。

主要な入口はGoogle Slidesの拡張機能です。原本・編集・出力はGoogle Workspaceで扱い、生成は利用を許可されたGemini Web、ChatGPT Web、Claude Webで行います。GeminiはWorkspace Webのみ、モデルAPIとWorkspace Studioは必須にしません。Google Slides拡張のコードはOSSとし、独立したWebサービスを提供する場合は後続のSaaSとして扱います。

現行のサイドバーも日常利用はブラウザで行えます。ただし、テンプレートの選び方、初回利用、根拠情報の入力、AI出力エラーの修正、運用配布までを営業向けの完成条件として定義できていませんでした。ローカルプラグインの導入成功は、この経路の完成を示しません。

## 利用者と責任

| 利用者 | 作業 | 日常利用の前提 |
| --- | --- | --- |
| 営業・企画・技術資料の一般作成者 | テンプレート選択、案件情報入力、AIとの受け渡し、内容・表示確認、反映・提出 | ブラウザと許可されたGoogle/AIアカウント。コード編集・CLI・個人の追加課金は要求しない |
| テンプレート担当者 | 原本整備、変更欄・容量・用途の指定、表示確認、承認、共有する原本の管理 | 会社で許可された管理環境。初期版のローカル管理・CLIはこの役割に限定 |
| 開発・配布担当者 | OSSのビルド、Google原本への設置、権限確認、処理系の更新 | 一度の技術的な設置と保守。営業へファイル設置やスクリプト実行手順を渡さない |
| ローカルAIエージェント利用者 | 共通仕様とSkill・CLIによる計画生成・検証 | 追加経路。営業向け機能の前提にしない |

テンプレート担当者もブラウザだけで整備したい場合には管理画面が必要です。一般作成者がブラウザだけで使えることと、管理者の全作業がブラウザだけで完結することは、別の受入条件にします。

## 営業の主経路

1. 組織が共有したテンプレート一覧から、用途と見本を見て原本を選びます。Googleの標準コピー操作で作業資料を作ります。最初の一覧はDriveの共有フォルダ・共有文書等でも構いません。新しい独立WebアプリやDrive全体のアクセス権は必須にしません。
2. 作業資料の「AI資料作成」を開きます。今回の目的、相手、顧客・案件の情報、使う商品情報を入力します。必須入力と不足する情報を業務の言葉で表示します。
3. システムが、その原本の版、利用可能なページ、容量、選んだ構成案、今回の情報を含む指示を生成します。「指示をコピー」から許可されたAIのWeb画面へ渡します。URLや検索パラメータへ案件本文を入れません。
4. AIの回答を、そのままサイドバーへ貼り付けます。利用者はJSONの構文、ID、ハッシュ、根拠IDを理解・編集する必要がありません。構造化JSONは内部の受け渡し形式として維持します。
5. ページ順、ページごとの文章、根拠・要確認事項、手修正との競合を業務の言葉で確認します。登録済みの原本ページから選択・繰り返し・順序変更を計画できます。用途別の構成案は初期値であり、全顧客へ同じ順序を強制しません。
6. 「確認した内容を反映」で既存ページを複製・更新します。実際のSlides上の表示を確認し、必要な手修正を行います。出力は会社で許可されたGoogle標準機能を使います。資料ファイルの保存・提出と、新しいアプリの導入は区別します。

初回のGoogle権限確認は発生し得ます。組織で必要な承認を事前に整理しても、利用者の同意画面が必ず無くなるとは主張しません。権限不足をコード入力や手動認証情報の設定で解決させず、担当者へ連絡できる状態にします。

### 画面へ追加する仕様

| 機能 | 利用者の操作 | システムが担当すること | 現状 |
| --- | --- | --- | --- |
| 用途・見本・版を見て選ぶ | 組織の一覧から原本を選ぶ | 原本と用途・版を対応させ、コピー後も同じ仕様を使う | 原本コピーの方式はある。一覧の提供と業務向け表示は追加 |
| 構成案 | 初回提案・比較検討・次の判断などを選び、必要に応じて調整 | 登録ページと用途から候補を作り、AIへ渡す | 自由な計画は対応。用途別の構成案UIは追加 |
| 根拠情報の入力 | 「商品説明」「商談メモ」等の名前と内容を入力 | 情報ごとのIDを付与し、指示・許可リスト・確認画面を対応させる | 現行は名前の一覧と本文の対応を人が入力。入力カードと自動IDは追加 |
| 回答の取り込み | AI回答全体を貼り付ける | 形式・版・登録欄・容量・根拠IDを検査する | 検査は実装済み。JSON編集を案内しない |
| 回答の修正 | 「AIへ修正依頼をコピー」を押す | エラーを業務の言葉へ変換し、直すべき欄と同じ仕様を含む修正指示を作る | エラー表示はある。修正指示ボタンは追加 |
| 内容確認 | 文章と要確認事項を読む | 根拠IDを利用者が付けた情報名へ変換する | 差分・要確認表示はある。情報カードとの対応表示は追加 |
| 作業途中へ戻る | 同じ資料を開き直す | 保留した反映内容を復元し、明示的な再試行を待つ | 実装・モック検証済み。反映前の入力下書き保存は追加候補 |
| 問題の切り分け | 表示された案内に従う | 技術的なエラーを隠さず、担当者向け詳細と一般利用者の次の操作を分ける | 読取専用診断はある。営業向け復旧案内は追加 |

IDの存在確認だけで内容の正しさを証明したとは扱いません。入力された情報の鮮度と、文章が根拠に対応しているかは別に確認します。原本PPTX全体や固定の会社資産を、既定でAIへ送信しません。

## テンプレートの構造化と管理

見た目はGoogle原本のネイティブ要素を維持し、ページの目的、変更欄、タグ、容量、版を共通仕様で表します。ローカルの原本・template.json・基準画像・承認記録を管理基準とする既存経路は維持します。Google側の原本と生成Catalogは、同じ版の公開先です。営業はローカルパックを持ちません。

初期の運用は、担当者が新しい版を整備・表示確認・承認し、Google原本へ設置して共有します。既存の作業資料は作成時の版を保持し、黙って別版へ更新しません。顧客名、日付、案件名、固定ページ番号等が原本に残ることを整備時に確認します。これらを自動入力する欄が必要なら、AIが書く欄とシステムが決定する欄を仕様で区別します。この区別は現行スキーマへ未追加です。

テンプレート担当者向けのブラウザ管理は次の追加機能として扱います。

- 原本のタグ候補を読取専用で表示し、担当者が変更可能な欄を選ぶ。
- ページ用途、欄の名前、容量、必須条件をフォームで編集する。
- 設定の候補を作り、検査・表示確認後に新しい版として公開する。Google上の自由な編集を承認済み版へ自動反映しない。
- 原本PPTX・共通仕様・基準画像をローカル管理へ戻せる形で出力する。どの版が管理基準かを明示し、自動の双方向同期は別機能にする。

既存のCatalog.gsは生成した静的設定です。上記のフォーム編集・公開・ローカルへの出力はまだ実装されていません。静的Catalogを書き換えるために営業へApps Script APIやプロジェクト編集権限を要求しません。管理機能を実装する際は、公開済み版を読む処理と候補を作る処理を分離します。

## ChatGPT Webの直接プラグインと追加経路

コピー＆貼り付けで使うChatGPT Webと、ChatGPT Webからツールを直接呼ぶプラグインを別の対応項目にします。後者はローカルSkillの同梱だけでは完成しません。

OpenAIの公式ドキュメントには、ChatGPT WebからMCPサーバーへ接続し、読取・書込ツールを使う経路があります。接続・使用はWorkspaceの権限等に依存します。対象アカウントで利用できるかは未確認であり、営業向けの必須条件にしません。

直接接続を追加する場合の構成は次のとおりです。

- 組織が許可した場所に認証付きのリモートMCPを設置する。営業のPCにサーバーやトンネルを常駐させない。個人のホスト付きサービスを提供するならSaaSとして扱い、プラグインの共通コードはOSSとする。
- list_templates、get_template_spec、validate_plan、prepare_preview、apply_plan等を共通仕様へ接続する。任意の座標やコードを受け付けない。
- prepare_previewで計画と対象の版・現在状態を結び付け、利用者が確認した内容だけをapply_planへ渡す。AIの計画生成と書き込みを同一の無確認操作にしない。
- Googleへ利用者の権限で接続し、対象原本・作業資料を確認する。複製、再試行、手修正保持を既存の検証器と同じ契約で扱う。
- モデル生成はChatGPTの会話が担当し、この経路のために別のモデルAPI課金を必須にしない。ただしサーバー運用、Google接続、各アカウントの利用条件は別に確認する。

現行の反映コードはgetActivePresentation()を使うコンテナ内の処理です。これをWebアプリとして公開するだけで外部MCPからそのまま使えるとは扱いません。外部経路には対象を明示する編集アダプター、認証、差分・状態の再検証、配布と実機試験が必要です。

Copilot CLI・Claude Code・Codex等は、同じ仕様を使う追加入口として維持します。現行は検証済みの計画をサイドバーへ戻す方式です。MCPの追加時にエージェントからの直接反映も検討します。Gemini Workspace Webからこの独自MCPを呼べることは前提にしません。

## 配布・権限・更新

最初は、技術担当者が設置したGoogle原本を共有し、利用者が作業コピーを作る方式を使います。公式にはコンテナのコピーにスクリプトが含まれますが、会社のコピー制限・同意・メニュー表示・共有ドライブでの運用は実機で確認します。営業にスクリプトの設置を依頼しません。

この方式では作業コピーごとにコードも残るため、修正を全資料へ一括反映できるとは扱いません。テンプレート版と処理系の版を区別し、保守すべき件数・重大な修正の配布・問い合わせ先を決めます。継続利用の規模で必要なら、組織管理のEditorアドオン等の配布へ移行します。アドオン利用可能という確認と、特定のアドオンの配布・権限の承認は同一ではありません。

独立したWebポータルは、複数原本の選択や一括管理が必要な場合の後続案です。URLがブラウザで開けるだけでは、外部サービスの利用許可やGoogleデータへの接続が済んだとは扱いません。Apps Script Webアプリを選ぶ場合も、利用者として実行するか所有者として実行するかで権限が変わるため、認証設計を別途行います。

## 受入条件と実装順序

| 検証項目 | 合格条件 |
| --- | --- |
| 新しい端末での利用 | 許可されたブラウザだけで、原本選択から反映・Google標準出力まで操作できる。ローカル実行環境を要求しない |
| 一般利用者の操作 | JSON編集、根拠IDの手入力、コードの設置、ターミナル操作を案内しない |
| 初回利用 | 原本からコピーし、必要な権限を確認すると利用できる。設置担当者の操作を営業の手順へ混ぜない |
| PCへの依存 | テンプレート担当者と開発担当者のPCが停止していても、公開済み原本で作成できる |
| AIの選択 | Gemini Workspace Webで基本経路を完了できる。ChatGPT等の契約・外部接続が基本経路を塞がない |
| AIの出力失敗 | 同じ仕様と対象欄を含む修正依頼を生成し、営業が構文を直さず再試行できる |
| 手修正・再試行 | 保持が既定で、選んだ欄のみ上書きする。確認後の変更や途中状態では停止し、案内を表示する |
| 表示と版 | 現物とPDFでブランド・折り返し・表を確認する。版違いを拒否し、登録だけを表示保証にしない |
| 保守 | 原本の管理者、処理系の版、更新方法、復元と問い合わせ方法が決まっている |
| 価値 | 過去資料の通常流用との比較に、入力・2回のコピー・AI待ち・確認・修正・書き出し・整備と保守の時間を含める |

開発の順序は、(1)営業向けの入力カード・構成案・修正依頼・初回案内、(2)ブラウザ経路の実Google試験と実務比較、(3)担当者向けの管理フォームと組織配布、(4)利用条件を確認したChatGPT Webの直接プラグインです。ChatGPT Webの直接接続は独立した対応項目として追跡し、ローカルプラグインの検証で代替しません。

ブラウザで使えることと、営業が進んで使うことは別です。コピー＆貼り付けを含む総作業時間が通常流用を上回るなら、その用途では採用を見直します。グラフ・可変図解・コード等が必須の資料も、現在の文字欄方式だけで十分とは判断しません。

## 仕様の自己レビュー

| 元の要望・今回の制約 | 判定 |
| --- | --- |
| 営業は承認済みのブラウザで完結 | 主経路の必須条件へ変更。実Google・企業設定の試験は残る |
| Geminiは会社推奨・Workspace Webのみ | コピー経路で維持。自動生成APIとStudioに依存しない |
| ローカルでテンプレート管理 | 担当者の管理経路として維持。営業のPCへ配布しない |
| ChatGPT利用者のプラグイン | Web直接接続を明示して追加予定へ。現時点では未達と記録 |
| Copilot CLI等・OSSへの参加 | 共通契約・公開資産の配布を維持し、営業の条件から切り離す |
| 独立Webサービスなら個人SaaS | 後続のホスト付きサービスとして区別。Google拡張のOSS利用には必須にしない |
| デザイン・正確さ・速さ | ネイティブ原本を複製し、内容・描画・総時間を別々に評価。まだ実務での達成は未測定 |
